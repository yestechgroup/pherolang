# AGENTS.md

Rust cargo workspace. `.mox` modeling sources compile to a Core IR artifact; backends (Rust codegen, JSON Schema) consume only that IR. Language reference: `docs/LANGUAGE.md`; expression spec: `docs/EXPRESSIONS.md`.

## What belongs in this file

Invariants, traps, and commands: what an agent must know before touching the compiler. **Never normative tables or field-by-field contracts** — the grammar lives once in the parser module docs and the wire/editor contracts live in `docs/`, each bullet linking its owner. State the consequence here; let the doc state the rule.

## Pipeline (crate ownership)

Surfaces are parsed in `rex-syntax` (logos lexer + chumsky parser, one parse/fmt entry point per surface), resolved/validated/lowered in `rex-driver` (salsa-based: resolve, validate, lower, navigation index, diagnostics), and land as versioned `rex-ir` artifacts that `rex-backend-rust` / `rex-backend-jsonschema` / `rex-backend-cedar` and downstream consumers ingest. The **normative grammar (EBNF) per surface lives exactly once** in the parser module docs — `crates/rex-syntax/src/parser/mod.rs` for the `.mox` family and `crates/rex-ifml/src/parser/mod.rs` for `.ifml`; docs link to it instead of restating it (`.rosetta`: external toolchain). A new surface is a table row, not an appended sentence.

- Backends must consume **only** `rex_ir::Model` (and, for Cedar, the `ActorModel` pair) — never the AST. Lowering happens in `rex-driver`.
- **One surface table, one compile pipeline**: `rex_driver::SurfaceKind` (`crates/rex-driver/src/surface.rs`) is the only extension map — the CLI's `is_*_file` helpers, the project snapshot's written-import dispatch, `verify`'s receipt kinds, and the LSP's `surface_for`/`surface_of_path` all delegate to it. `commands/pipeline.rs::compile_one` is the CLI's one per-surface dispatch (exhaustive, no `_` arm). A new surface is one `of_extension`/`ALL` edit, one pipeline arm, and the host's own arm — never a new `is_*_file` tower. Contract: [docs/GRAPH.md](docs/GRAPH.md#one-surface-table-one-compile-pipeline).
- The serialized IR is a versioned wire format: camelCase, adjacent tagging, `formatVersion` gate. Contract and rules live in the `rex-ir` crate docs. New fields must be `#[serde(default)]` (+ `skip_serializing_if`) so body-less/vocabulary-less models stay **byte-identical** — golden tests enforce this.
- **Domain imports**: every compile entry point takes one `DomainImports` bundle (`SchemaImports`/`SigilImports` inside, keyed `(mox path, import path)`); `DomainImports::default()` provides nothing (→ `imported schema/sigil '<path>' was not provided`). The CLI resolves import content from disk (paths relative to the importing file — `.mox` sigil imports also walk the named file's directory for transitive rosetta imports; see Gotchas for the per-surface rules); the driver stays filesystem-free. For `.actor`/`.ddd` compiles the bundle carries each imported domain's import content keyed by the domain's path, so policies and designs target lowered rosetta/schema types.
- Plus `rex-expr` (expression parser/typechecker), `rex-vocab` (providers/lockfile), `rex-runtime` (generated code's support lib), `rex-backend-common` (backend-shared utilities: canonical JSON key order, the snake_case instance-id convention, the generated-file writer), `rex-lsp`, `rex-cli` (the `rexlang` binary), `rex-verify` (Creusot-specified semantic-graph kernel — contracts compile away on stable, proofs via `cargo creusot -p rex-verify` are run locally, not in CI; the proof-obligation register's **source** is `docs/verification/register.json`, generated into `docs/VERIFICATION.md`, and every `#[trusted]` needs a row), and `rex-evidence` (the evidence spine: the machine-readable register and verification receipts — pure, serde/serde_json/sha2, no filesystem or compiler access).

## Commands

```sh
scripts/ci-local.sh              # THE gate: build, test, clippy, fmt, docs — every step must report *-OK before pushing
scripts/ci-local.sh audit        # the supply-chain gates (cargo deny check + cargo audit) — CI runs them as separate fast jobs
scripts/ci-local.sh build|test|clippy|fmt|docs    # one CI step at a time
scripts/dev-test.sh [args...]    # `cargo test` with the CI env (debuginfo=0, no incremental, TMPDIR=target/tmp, --jobs 2) — the cheap path for "just run the tests" (issue #261)
cargo test -p rex-driver --test navigation      # one test suite
cargo run -p rex-cli -- check tests/conformance/                            # project mode + the union integrity pass: one snapshot of every supported surface under a dir; each file checks independently with its imports resolving map-first from the snapshot, then the standalone artifacts cluster into import-connected applications and the cross-layer wiring is diagnosed per application (formatter-golden `X.fmt.<ext>` artifacts are skipped — they are outputs whose imports/vocab resolve next to their sources, not standalone models)
cargo run -p rex-cli -- build tests/conformance/ -o target/rex               # project-mode artifact emission: one `<input path>.json` per file under the out dir (default `target/rex`), each the `rexlang ir` artifact for its surface
cargo run -p rex-cli -- graph build examples/ -o target/examples.graph.json   # one semantic graph artifact across every surface under the tree: import-connected applications, nodes, edges; display paths are base-relative POSIX
cargo run -p rex-cli -- graph query examples/artifacts/examples.graph.json affected-by 'capability:support/support.actor#Support.RaiseRefund'   # artifact-only query (`-` = stdin): node / list / affected-by / dependencies, one versioned envelope each
cargo run -p rex-cli -- graph query tests/conformance/graph/app.graph.json separation-of-duty --pair App.RaiseRefund App.ApproveRefund --fail-on-findings   # cross-policy analytics: separation-of-duty / monotonicity / dead-capabilities / reachability (exit 1 on a definite finding)
cargo run -p rex-cli -- explain E0104                                        # explain one diagnostic code from the rex-diagnostics registry (--list: the allocation ledger + every code)
cargo run -p rex-cli -- verify <files...> -o <receipt.json>                 # emit a verification receipt: source closure + artifact hashes + the register's rows, canonical and deterministic
cargo run -p rex-cli -- verify --check <receipt.json>                       # validate a receipt standalone — no register, models, toolchain, or network
cargo run -p rex-cli -- verify --check-fresh <receipt.json>                 # regenerate from the receipt's own inputs and byte-compare (the CI freshness gate)
REX_UPDATE_FIXTURES=1 cargo test --workspace    # regenerate golden files
REX_UPDATE_FIXTURES=1 cargo test -p rex-verify  # regenerate the register tables in docs/VERIFICATION.md (hand-edit register.json, never the tables)
```

CI (`.github/workflows/ci.yml`) **invokes `scripts/ci-local.sh` for every gate** (build, tests, clippy, fmt, docs) — the script is the single source of truth for the gate sequence and the `rexlang fmt --check` fixture-glob list (`FIXTURE_FORMAT_GLOBS`), so a new fixture directory is a one-file edit and local/remote can never drift (issue #121). CI also runs two fast supply-chain jobs: `cargo audit` (advisories — must stay at zero) and `cargo deny check` (advisories/licenses/bans/sources per `deny.toml`); the script's `audit` subcommand replicates both locally. A warning anywhere is a failure.

## Testing quirks

- **Golden fixtures** under `tests/conformance/` (IR artifacts, wire/api schemas, instances, fmt output) are byte-compared. Regenerate with `REX_UPDATE_FIXTURES=1`, then read the diff — goldens are the spec. Changing any emitter usually invalidates several goldens; body-less/vocabulary-less models must stay byte-identical.
- **Scratch-crate e2e** (`rex-backend-rust/tests/codegen_end_to_end.rs`): tests generate Rust code into a *separate cargo project* under `target/scratch/` and run `cargo test` in it (tries `--offline` first). Deleting `target/scratch/` is always safe; first run recompiles it (~10s). The scratch crate must keep `[workspace]` (empty) to stay out of ours.
- **Examples are CI-tested** (`examples/`): `examples_conformance` compiles each example, generates it into `target/scratch/rex-examples-test`, and runs behavioral assertions; `examples_schemas` validates `examples/instances/*.json` against generated wire schemas; `examples_cedar` (rex-backend-cedar) validates the `support` pair's Cedar output with the real `cedar-policy` crate under strict validation; `examples_artifacts` (rex-driver) compiles the artifact-surface examples (`.evt`/`.ddd`/`.uc`/`.deploy`/`.cmmn`) and byte-compares them against `examples/artifacts/` goldens; rex-backend-cmmn's examples test lowers `support.cmmn` to the cmmn-rs `CaseDefinition` JSON (`examples/artifacts/support.case.json`). Adding an example means adding its scratch assertions + instance (domain surfaces) or its artifact golden (artifact surfaces) — the harness fails otherwise. The domain-example list is hardcoded in three places: `examples_flow.rs`, `examples_schemas.rs`, and `rex-cli/tests/cli/`; the artifact-surface lists live in `crates/rex-driver/tests/examples_artifacts.rs` (with per-extension list↔disk sync tests); the `.ifml` examples (`examples/*/*.ifml`) have their own list in `crates/rex-ifml/tests/examples.rs` (compile + type-check + fmt-canonical + manifest byte-goldens under `examples/artifacts/<name>.manifest.json`); `rex-cli/tests/cli/` black-box `check`s the artifact examples too (`ARTIFACT_EXAMPLES`).
- **No network in tests**: `HttpProvider` is only URL-template unit-tested. `rexlang vocab fetch` is the only command that fetches.
- **The editor is one graph snapshot**: `.mox` drives the salsa session + `NavigationIndex`, `.ifml` its own one-shot compile + outline, and **every other surface** navigates through a directory-scoped graph snapshot, cached per directory and open `(uri, version)` set and rebuilt incrementally from a per-file content-hash memo. Diagnostics are each surface's own compile, never a second one. Resolution is the graph index's, locations the span tables'; an unbindable reference yields **no location, never an error**, and rename is declaration-owned and document-scoped (a cross-document rename is refused, naming the owning file). Contract: [docs/GRAPH.md](docs/GRAPH.md#the-lsp-contract).
- **LSP tests are in-process** via `LspService` + client socket (`tower-lsp` 0.20); the only subprocess test is the framed stdio handshake in `rex-cli`. Tests assert a compile counter (`initialized_service_counted`), never timing. The tower-lsp client socket is a **capacity-1 channel**: tests must interleave reads (`next_publish`/`drain_socket`) with opens or the server's publish send deadlocks the handler. The matrix tests live in `crates/rex-lsp/src/server/tests/graph.rs` (a temp copy of `tests/conformance/graph/app.*` plus the files the matrix needs).
- Wire-schema conformance validation uses the `jsonschema` crate against the committed golden schema; proptest suites (rex-backend-rust scratch, rex-backend-jsonschema) generate instances and validate round-trips — treat shrinking counterexamples as real bugs, not flaky tests.
- On this machine, `/tmp` is a small tmpfs and rustdoc doctest **linking SIGBUSes (or hangs) writing there**; run doctests (or full `cargo test`) with `TMPDIR` pointed at a disk-backed directory. Watch for orphaned `cargo`/`rustc`/`rust-lld` processes after killed builds — they stampede the load average and lock `target/`. **This hit CI too** (Oct 2026 incident: the runner's rex-driver doctests died with `ld terminated with signal 7 [Bus error]` and main stayed red for a day) — `.github/workflows/ci.yml` now frees runner disk, points `TMPDIR` at `target/tmp`, and caps the test step at `--jobs 2`; `scripts/ci-local.sh` replicates the five CI steps locally. A `signal 7` in CI's Doc-tests section is resource exhaustion — check `df -h` in the log, don't hunt a compiler bug. Before pushing: run `scripts/ci-local.sh` until every step reports `*-OK`. Before branching: check main's latest run is green.

- **The build dir is a disk budget** (issue #261): cargo places integration-test binaries under `target/debug/build/<pkg>/<hash>/out/` and **never collects old hashes**; with the workspace default `debuginfo=2` a single worktree reached 104–119 GB (one crate's `build` dir alone: 104 GB). At 100% disk the symptom is exactly the one above — a doctest link dying with `ld terminated with signal 7 [Bus error]` — disk-induced, not a compiler bug: check `df -h` before hunting one. `scripts/ci-local.sh` exports `RUSTFLAGS="-C debuginfo=0"` + `CARGO_INCREMENTAL=0`, prints `df -h .` / `du -sh target` before the build step (and warns, never fails a gate, when free space is under `REX_DISK_MIN_GB`, default 20 GB), and clears stale `target/tmp` before the test step (it is recreated); `scripts/dev-test.sh` gives a plain `cargo test` the same env + `--jobs 2`. Reclaim with `rm -rf target/debug/build/rex-*` (**workspace crates only** — external deps survive; never delete `target/debug/build` wholesale, it is the live cache). Explicit decision: **no `[profile.dev] debug = 0`** in `Cargo.toml` — debugging the compiler with `debug=2` is valuable, and a profile change would alter fingerprints for every contributor and CI; the wrapper is the cheap path.

## Gotchas

- **Verification receipts are goldens too** (issues #197/#206/#207): `examples/artifacts/support.receipt.json` embeds the register's hash and rows, every `sources` hash, and every artifact hash, so *any* change to a source in the closure, an artifact golden, the register, or the generator version makes it stale. The `scripts/ci-local.sh receipt` step (CI step 5/6) fails with the exact regenerate command; run it and read the diff. `--check` is offline validation (receipt + sibling artifacts only); `--check-fresh` is the gate (it re-derives artifact goldens and re-reads the register). `mutantKilled` is `null` for every row plus `limits: ["mutants-unrecorded"]` until #208 lands — that is the honest interim, not a gap to paper over. Staleness classes and the schema live in `docs/RECEIPTS.md`.
- The proof-obligation register is **generated** (issue #203): `docs/verification/register.json` is the source — hand-edit it, never the tables — and the block between the `BEGIN/END GENERATED REGISTER` markers in `docs/VERIFICATION.md` is rendered from it by `REX_UPDATE_FIXTURES=1 cargo test -p rex-verify`. The drift gate (`crates/rex-verify/tests/trusted_register.rs`, the #89 lineage) fails on: a dead evidence pointer (missing file or absent `fn <symbol>`), a status outside `proved`/`tested`/`argued`/`assumed` (`"verified"` is rejected by name), an `argued`/`assumed`/mirrored row without a `trigger` + ISO `review` ≥ `reviewedAt`, a hold row without reason/trigger/review, a `#[trusted]` with no `trusted[]` entry, or a `trusted[]` entry with no `#[trusted]` in the tree (the check is **bidirectional**; the old one-way substring test is gone). `rex-evidence` owns the parse/validate/render; the gate owns the filesystem resolution.
- `rexlang graph build` (issue #240) is **derived post-compile — never parsed**: `commands/graph.rs` expands inputs exactly like `check`/`build` and hands `rex_driver::graph::build` each file's already-computed typed artifact and resolved imports (one `GraphInputs` bucket per surface; never a re-read or re-compile), best-effort over the compiling subset (exit `1`). There is no `rexVersion`, determinism is the builder's, and the kind vocabulary is **open** — a new kind is a new string constant, not an enum variant. Golden: `REX_UPDATE_FIXTURES=1 cargo test -p rex-cli --test cli graph`. Contract: [docs/GRAPH.md](docs/GRAPH.md#the-rexlang-graph-build-command).
- `graph query` and the four cross-policy analytics run on the **artifact alone** (`GraphIndex`) — no sources, no recompile, no resolver — one versioned envelope each (`GRAPH_QUERY_FORMAT_VERSION`). Closures walk non-ownership edges reverse and `memberOf`/`contains` forward (`dependencies` mirrors it); every analytic stays **per application**, treats `when` guards as satisfiable, and never reports `unknown` (an opaque `cedar` grant) as a finding. `--fail-on-findings` exits `1` only on a definite finding. Contract: [queries](docs/GRAPH.md#queries), [analytics](docs/GRAPH.md#cross-policy-analytics); regenerate with `REX_UPDATE_FIXTURES=1 cargo test -p rex-driver --test graph_analytics`.
- **The span tables and the graph share one node table**: one pure, never-panicking builder per surface (`crates/rex-driver/src/navigation/`) derives every definition through `graph::ids` — the single naming source — and `IndexedReference`s carry `target_kinds` hints only, never a binding. The anti-drift gate is `every_indexed_definition_maps_to_exactly_one_graph_node` + `span_slices_equal_the_written_name` (`crates/rex-driver/tests/navigation.rs`) over all nine surfaces of `examples/support/support.*`, with exactly **three documented exclusions**: the `file` node, the `.ifml` `flow` node (both name a host fact), and the `.deploy` `platformCapability` node (a driver vocabulary word, not a declaration — the editor lands on the word's first `requires` mention). Builders and corpus: [docs/GRAPH.md](docs/GRAPH.md#span-tables).
- `check_integrity` (issue #114, register row V12) is the union integrity pass `rexlang check <dir>` hosts: a pure function over path-tagged artifact buckets, span-less, with five error checks and two **warning** capability checks (their compile-time joins are the language errors; this pass is the lint channel since rexlang#128). Pools follow the **application, not the directory** — the CLI hosts it in phase 2 only, and its capability lint stays unprinted for files phase 1 already failed. Traps: `agent` is a keyword (never a bare `.ddd` param name), a standalone `cedar { … }` grant serializes an empty capability name (coverage skips it), action→op binding is ASCII-case-insensitive. Codes: [docs/GRAPH.md](docs/GRAPH.md#union-integrity) + [docs/DIAGNOSTICS.md](docs/DIAGNOSTICS.md).
- Capability nouns are classified against the aggregates (rexlang#144): a capability granted on a **non-root** aggregate member warns (`a non-root aggregate member`, naming and pointing at the root when derivable); value, root, and no-design cases stay silent. The table is built only when designs are provided **and** every domain lowered, and the `.ddd` inline-actors path always passes none (actor lowering and the design registries never co-occur there). Rules: [docs/DDD.md](docs/DDD.md#capability-nouns-on-aggregate-members-rexlang144).
- Machines are closed over their enum (V13): every machine state must be a literal of the machine's enum type, and `.ddd` `when` conditions (transition guards, service/repo op conditions) must type as boolean — the `.actor`/`.deploy`/`.cmmn` rule. Obligations are a declared vocabulary (V14): entries' `obligation` names resolve against the union of actors blocks' `obligation <name>;` declarations (purpose semantics), and action declarations' `target:` resolves to a domain class (E0109, skipped when the flow has no domains).
- `rex-parser` is the **only** crate that permits `unsafe` (documented in its Cargo.toml): chumsky 0.10's `Input` trait requires `unsafe fn` implementations for the shared byte-span `Tokens` input. `rex-syntax` keeps the workspace `unsafe_code = "forbid"` and re-exports the shared `Span`, `ParseError`, and `Tokens`; don't copy the input impl into a surface crate. `rex-expr` deliberately uses chumsky `Stream` + `.boxed()` levels instead (unboxed towers overflow the 2 MB test-thread stack).
- Comments: `lex()` drops comments for the parser; `lex_with_comments()` is what `fmt` uses. Parser spans are **byte offsets**; LSP maps them to UTF-16 (`rex-lsp/src/position.rs`).
- `id`/`readonly` are contextual identifiers, not keywords — they remain usable as feature names. Actor words (`actors actor agent capability grant permit forbid when obligation on never_both delegation purpose cedar import`) ARE real keywords, escapable with `^`. `schema`/`sigil` are contextual (only after `import`); `to` is contextual on delegation lines.
- `when` conditions are **fully type-checked** against the capability's class (single-file and `.actor` compiles) via rex-expr; the Cedar backend separately rejects constructs it cannot map at generate time (errors name the capability). Multiple obligations on one grant entry serialize as ONE Cedar annotation with comma-joined values (Cedar rejects duplicate annotation keys).
- `cedar-policy` is a **dev-dependency of rex-backend-cedar only** — the backend never links Cedar. It enables serde_json's `preserve_order`, which unifies workspace-wide and flips `serde_json::Map` to insertion order; emitters must canonicalize key order themselves (the shared `canonical_key_order` in `rex-backend-common`) or goldens drift.
- `rexlang fmt` dispatches by file extension (`.mox` vs `.actor` vs `.ddd` vs `.evt` vs `.deploy` vs `.uc` vs `.cmmn` vs `.ifml` formatters); stdin is treated as `.mox`.
- **Canonical fixture vs formatter source**: each artifact surface has canonical conformance models the CI fmt gate covers — `.evt` → `tests/conformance/events/`, `.deploy` → `deploy/`, `.uc` → `usecases/`, `.cmmn` → `cmmn/`, `.dmn` → `dmn/` — plus a deliberately **non-canonical** source under `tests/conformance/models/<surface>.<ext>` that the formatter golden-compares; never cite the model copy as canonical or "fix" its spacing. `FIXTURE_FORMAT_GLOBS` in `scripts/ci-local.sh` is the one list of what the gate formats.
- `.dmn` words are all contextual (`crates/rex-syntax/src/dmn.rs`) except `version` (the one real lexer keyword) and the shared `import`; element names share one namespace per model. Decision tables are **external markdown**, one table per file, whose contents the host provides keyed by the path as written. Trap: `agent` is an `.actor` lexer keyword — never an unescaped `.dmn` input name (`support.dmn` uses `helper`). Vocabulary: [docs/DMN.md](docs/DMN.md#vocabulary).
- `.deploy` words are all contextual (tables in `crates/rex-syntax/src/deploy.rs`); `->` (`Token::Arrow`) is the one new lexer token, and setting *values* accept keyword tokens (`container` is a `.mox` keyword but an ordinary word in value position — the qname-segment rule). Policies are rex-expr conditions typed against a synthetic settings universe (`DomainTypes::insert_class`, never a fake `Model`) and evaluated by the driver's constant evaluator against effective settings (component baselines ⊕ profile defaults ⊕ overrides).
- `.actor` import resolution lives in the CLI (paths relative to the `.actor` file, read from disk); the driver receives texts only and stays filesystem-free (`compile_actors_str`). Import-path strings must match provided domain paths exactly.
- `.mox` `import schema "<path>" as <Alias>` registers a **nominal, feature-less class** (alias, else the file stem) in the package namespace — JSON content is validated but never lowered into features (v1 is opaque). `schema` is a contextual keyword (only after `import`); the driver stays filesystem-free via the `DomainImports` bundle every compile entry point takes (`SchemaImports`/`SigilImports` inside, keyed `(mox path, import path)`) — the CLI resolves paths relative to the `.mox` file, `DomainImports::default()` provides nothing (→ `imported schema '<path>' was not provided`). `rexlang fmt` hoists the declarations into a section directly after `package`.
- `.ifml` imports are keyed by the resolver as `(importing-file identity, import-as-written)`; hosts gather them through `rex_ifml::walk_ifml_imports` (shared traversal — the CLI collector and the examples harness are fetch closures over it) and must provide under the same identities or nested imports miss. The reference pattern library lives in `patterns/ifml/` — domain-agnostic modules composed via `use` inside module bodies; its wire shape is pinned by goldens under `tests/conformance/ifml/patterns/`.
- `rex_driver::workspace_imports` is the host-side bridge for `import schema`/`import sigil` disk resolution (the driver core stays filesystem-free): the CLI and the LSP both gather through it; `collect_for_source` re-keys under a driver key that differs from the disk path (the LSP keys documents by URI).
- `compile_ifml_lenient` is the LSP's entry: the strict `compile_ifml_str` Ok/Err contract stays, lenient always returns the (partial) compilation with its import index — completions/definitions work on broken code. `.ifml` references/rename match BY NAME across every open snapshot (a module's uses live in dependents the focused import closure never sees); rename validity is the string surface's (non-empty, no quotes/backslashes/newlines).
- `rexlang ir --expand <file.ifml>` inlines `use` sites into the resolved module contents (overrides applied, composition recursed) — the DEFAULT artifact keeps use references; expansion is opt-in and never serialized back into the strict artifact.
- The `.ifml` formatter is **token-based, not IR-based** (the parser's lexer drops comments) and is pinned to byte-identical round-trip of the canonical fixtures `tests/conformance/ifml/app.ifml` and `tests/conformance/ifml/cli.ifml` (commands) — those tests are the layout spec (80-column inline budget, call-argument binding blocks always expand, `column` runs align their `->`, declaration headers always expand (`view`/`command`/…), structural blank before `component`/`container`/`use`/`field`/`column`/`command`, interior source blanks preserved collapsed). Changing layout rules means re-formatting every `.ifml` fixture, example, and pattern file in the same commit.
- The `.ifml` checker (`check_ifml`) **silently defers** what the shared expression language cannot type (bare calls, `%`, regex ops, non-integral numbers, `Float`/`DateTime`, generic module-input types, prompt names and generic command types, everything with `domains: None`) — the documented generation-time contract: don't "fix" the skips into errors. Deferral list: [docs/IFML.md](docs/IFML.md#typed-bindings).
- `.ifml` `.actor` imports are **load-bearing** (Phase A of #117): hosts compile them into `ActorModel`s for `check_ifml_with_actors` — an empty actors slice skips the authorization pass entirely (the `domains: None` contract). The CLI hard-errors on a missing or non-compiling policy; the LSP degrades to no authorization checking (open documents win over disk). `requires:`/`roles:` resolve bare-name union-wide against capability/actor tables; spans come from the index's `auth_sites` (never serialized — the IR is unchanged). E0107/E0108 live in rex-ifml's check/ directory; E0104–E0106 there are the interaction cross-reference — every diagnostic code is allocated in the central `rex-diagnostics` registry (`rexlang explain --list`); a new code is a table row there, never a local constant.
- The `.ifml` cross-reference (E0104–E0106), authorization (E0107/E0108), and decision passes diagnose **the entry file plus every module body it instantiates**; sibling modules the app never `use`s stay inert, which is what keeps the pattern library's app-facing names honestly undeclared. `navigate` targets are views **or containers**. Every diagnostic code is a row in the central `rex-diagnostics` registry (`rexlang explain --list`), never a local constant. Passes: [docs/IFML.md](docs/IFML.md#interaction-references).
- The control/route manifest (`rexlang manifest <file.ifml>`, issue #118) is derived **post-check**, so every edge target is declaration-backed by construction; controls come from the **expanded** view tree, routes/actions/commands from the entry file, and `data:`/`target:` resolve to `(package, class)` only when the host provides a domain union and the name resolves uniquely (the bare spelling always rides along). `IFML_MANIFEST_FORMAT_VERSION` is independent, and it is deliberately not a classified kind in `artifact_check`. Contract, goldens: [docs/IFML.md](docs/IFML.md#controlroute-manifest).
- `.cmmn` compiles against five import buckets (raw `.mox` plus pre-compiled `.evt`/`.actor`/`.ddd`/`.dmn` pairs); plan items and case-file items share one namespace per case, and `when` conditions type-check against a synthetic case universe. `rex-backend-cmmn` consumes `(CmmnModel, domain Model)` and lowers only the FEEL-translatable rex-expr subset — event on-parts and plan-item predicates in `when`s compile but are named backend rejections (engine gaps, not authoring errors). Buckets, universes, vocabularies: [docs/CMMN.md](docs/CMMN.md#resolution--validation).
- Typed expression checking for ANY surface goes through `rex_expr::DomainTypes` (the public class/named-type index: `from_model`, `merge`, `insert_class`; `TypeContext` is a compatibility alias). Build/merge a `DomainTypes` rather than synthesizing a fake `rex_ir::Model` to call `TypeContext::from_model`.
- rex-expr resolves `EnumName.Member` through the `DomainTypes` enum-member registry (rule L3 of `docs/EXPRESSIONS.md`; fed by `from_model`/`insert_enum`), a non-member string literal compared against an enum-typed operand is a closed-set error, and the String-status guard lint warns use-based on `when`/filter guards but skips empty-string sentinels (rexlang#142).
- `rust` op bodies are emitted **verbatim** into the generated method; an `expr` body is parsed/typed/lowered at generate time (errors name the operation); no body ⇒ no generated method. Sigil functions are the twin: the `"rosetta"` target is carried and never emitted, a statement-bearing `func` also carries a driver-checked `"rune"` body, and NO `"rune"` target means the `todo!()` stub — a present-but-invalid one is a hard generate-time error. `returnMultiplicity` shapes the return type (`0..*` → `Vec<T>`, `0..1` → `Option<T>`). Contract: [docs/BACKENDS.md](docs/BACKENDS.md#the-serialized-artifact-contract-summary).
- Salsa session pattern (driver): `Database::new()` (Clone), `SourceFile::new(&db, path, text)`, `file.set_text(&mut db).to(...)`; tracked fns return rich `Clone + PartialEq` types (no Hash needed).
- `docs/EXPRESSIONS.md` rules R1–R4 are test-citable contracts (overflow, null-safe equality, Option propagation, division); lowering changes must keep them aligned.
