# 0003 — Compiler-backed highlighting is the source of truth

- **Status:** Accepted, 2026-11-17
- **Issue:** pherolang#294 (SH8, epic pherolang#286)
- **Supersedes:** nothing; it records the D1/D5 decisions the SH epic shipped
- **Related:** [HIGHLIGHTING.md](../HIGHLIGHTING.md),
  [ADR 0002](0002-static-hover-reference-panels.md)

## Context

Phero Lang has nine surfaces and two front-end lexer families
(`phero-syntax` for the `.mox` family, `phero-ifml` for `.ifml`). Before epic
SH, three consumers each needed to know the language's vocabulary:

- the marketing site rendered every block through
  `site/packages/ui/src/CodeBlock.astro` as plaintext;
- the docs site used Starlight/Expressive Code/Shiki, which knows nothing
  about `.mox`, `.ddd`, `.evt`, `.deploy`, `.uc`, `.cmmn`, `.dmn`, `.actor`,
  or `.ifml`;
- editors had no grammar, and the LSP had no semantic tokens.

The obvious cheap fix — a hand-written TextMate grammar plus a site-side
keyword list — is a second language definition. It drifts the first time a
lexer keyword changes, and it cannot represent parser state: contextual words
(`service`, `decision`, `logic`, `realizes`, `inventory`-style qname values),
declaration names, or `.ifml` strings that name declarations. The drift is
silent: the site keeps building and quietly lies about the language.

The epic's two deciding rules were:

- **D1 — the compiler is the source of truth.** Highlighting must not drift
  from the lexer/parser. TextMate is generated from the same metadata, never
  hand-authored as a separate vocabulary.
- **D5 — TextMate is a compatibility renderer.** Editors and the static
  fallback use generated grammars; hand edits to generated files fail a
  generator check.

## Decision

One Rust crate, `phero-highlight`, owns the taxonomy, the nine-surface
registry, the engine, and the renderers. It consumes the existing lexers and
spanned ASTs; it contains **no second parser** and no surface keyword table.
The word tables remain owned by `phero-syntax::words` and
`phero_ifml::words`, where drift tests already tie them to the lexers and the
parser EBNF.

Every consumer reads one of two artifacts derived from that model:

1. the versioned `pherolang highlight` JSON/HTML stream, consumed by the
   static sites and (through the same span stream) the LSP; and
2. the generated TextMate grammar + language configuration package under
   `site/packages/highlighting/`, consumed by editors and the static
   fallback.

The site never registers the generated grammar in the browser and never runs
the compiler at build time. It looks up a committed, content-addressed span
entry (`site/data/highlighting/spans.json`) generated by the CLI. A missing
entry renders plaintext **and** marks the block, and the site gate fails; a
silent fallback is not allowed.

## Alternatives considered

- **Hand-authored TextMate grammar only.** Rejected: it is a second
  vocabulary, it cannot see parser state, and it drifts silently. It would
  also make the LSP and the site disagree with the compiler by construction.
  A generated grammar keeps the editor compatibility while the compiler
  remains the source.
- **A site-side keyword/classifier list.** Rejected for the same reason, and
  it is explicitly forbidden by the quality gates: adding a parser keyword
  must never require editing `site/` or `phero-highlight`.
- **Shiki/Expressive Code grammars at build time.** Rejected as a fourth
  vocabulary. The docs app integrates at `postprocessAnalyzedCode`/
  `postprocessRenderedLine` and only splits Expressive Code's existing text
  nodes into the compiler's byte ranges; the frame, copy button, line
  numbers, and theme switching remain Expressive Code's.
- **Run the compiler per request or per page build.** Rejected: the site must
  build offline and deterministically, and a compiler dependency at request
  time is a runtime service the static deployment does not have. The
  committed artifact plus a freshness gate is the boundary.
- **A WASM compiler in the browser.** Deferred with the SH7 editor decision
  (ADR 0002); it is the right shape only when editing, completion, or
  diagnostics become requirements.

## Consequences

- A new keyword or surface is one owner-table edit plus corpus/golden
  regeneration; the registry, site, and grammars cannot silently disagree.
- The goldens are the spec: `tests/highlight/`, the corpus summaries, and the
  generated grammar package are byte-compared, so a hand edit fails.
- Contextual words in generated grammars are necessarily line-start
  heuristics. The divergence is measured against the compiler artifact by
  `site/scripts/check-grammars.mjs` and documented in
  [HIGHLIGHTING.md](../HIGHLIGHTING.md#textmate-versus-the-compiler); it is
  not asserted away.
- The released binary is a consumer contract. `pherolang highlight` must be
  in the release before the site can claim released-binary freshness; until
  then the documented source-built exception applies and release acceptance
  stays blocked (SH8).
- The site artifact carries no colours and no paths. Themes stay in
  `site/packages/tokens/`, measured by the contrast/a11y gates.
