# AGENTS.md

Rust cargo workspace. `.mox` modeling sources compile to a Core IR artifact; backends (Rust codegen, JSON Schema) consume only that IR. Language reference: `docs/LANGUAGE.md`; expression spec: `docs/EXPRESSIONS.md`.

## What belongs in this file

Invariants, traps, and commands: what an agent must know before touching the compiler. **Never normative tables or field-by-field contracts** — the grammar lives once in the parser module docs and the wire/editor contracts live in `docs/`, each bullet linking its owner. State the consequence here; let the doc state the rule.

## Pipeline (crate ownership)

Surfaces are parsed in `phero-syntax` (logos lexer + chumsky parser, one parse/fmt entry point per surface), resolved/validated/lowered in `phero-driver` (salsa-based: resolve, validate, lower, navigation index, diagnostics), and land as versioned `phero-ir` artifacts that `phero-backend-rust` / `phero-backend-jsonschema` / `phero-backend-cedar` / `phero-backend-ddd` and downstream consumers ingest. The **normative grammar (EBNF) per surface lives exactly once** in the parser module docs — `crates/phero-syntax/src/parser/mod.rs` for the `.mox` family and `crates/phero-ifml/src/parser/mod.rs` for `.ifml`; docs link to it instead of restating it (`.rosetta`: still `crates/sigil-syntax` until RN9). A new surface is a table row, not an appended sentence.

- Backends must consume **only** `phero_ir::Model` (and, for Cedar, the `ActorModel` pair) — never the AST. Lowering happens in `phero-driver`.
- **One surface table, one compile pipeline**: the surface identity lives once in `phero_parser::Surface` (`crates/phero-parser/src/surface.rs`) — one enum, one `ALL`, one extension table — re-exported as `phero_driver::SurfaceKind` and `phero_highlight::Surface`. The CLI's `is_*_file` helpers, the project snapshot's written-import dispatch, `verify`'s receipt kinds, and the LSP's surface decode all delegate to it. `commands/pipeline.rs::compile_one` is the CLI's one per-surface dispatch (exhaustive, no `_` arm). A new surface is one enum edit (its `of_extension` arm, `ALL` entry, id/display/alias rows) plus the per-surface rows of each host — never a second enum or a new `is_*_file` tower. Contract: [docs/GRAPH.md](docs/GRAPH.md#one-surface-table-one-compile-pipeline).
- The serialized IR is a versioned wire format: camelCase, adjacent tagging, `formatVersion` gate. Contract and rules live in the `phero-ir` crate docs. New fields must be `#[serde(default)]` (+ `skip_serializing_if`) so body-less/vocabulary-less models stay **byte-identical** — golden tests enforce this.
- Core IR `Feature.id` is an **intra-publication ordinal** (0-based declaration index in one published artifact), not a cross-publication identity: inserting/removing/reordering renumbers later slots. Consumers key continuity on `(package, class name, feature name)`; a rename is a new identity (DF2 #325, register V10).
- **Domain imports**: every compile entry point takes one `DomainImports` bundle (`SchemaImports`/`SigilImports` inside, keyed `(mox path, import path)`); `DomainImports::default()` provides nothing (→ `imported schema/sigil '<path>' was not provided`). The CLI resolves import content from disk (paths relative to the importing file — `.mox` sigil imports also walk the named file's directory for transitive rosetta imports; see Gotchas for the per-surface rules); the driver stays filesystem-free. For `.actor`/`.ddd` compiles the bundle carries each imported domain's import content keyed by the domain's path, so policies and designs target lowered rosetta/schema types.
- Plus `phero-expr` (expression parser/typechecker), `phero-vocab` (providers/lockfile), `phero-runtime` (generated code's support lib), `phero-backend-common` (backend-shared utilities: canonical JSON key order, the snake_case instance-id convention, the generated-file writer), `phero-lsp`, `phero-highlight` (the highlighting taxonomy, ten-surface registry, engine and JSON/HTML renderers — consumes the lexers/ASTs, never a second grammar), `phero-cli` (the `pherolang` binary), `phero-verify` (Creusot-specified semantic-graph kernel — contracts compile away on stable, proofs via `cargo creusot -p phero-verify` are run locally, not in CI; the proof-obligation register's **source** is `docs/verification/register.json`, generated into `docs/VERIFICATION.md`, and every `#[trusted]` needs a row), and `phero-evidence` (the evidence spine: the machine-readable register and verification receipts — pure, serde/serde_json/sha2, no filesystem or compiler access).

## Commands

```sh
scripts/ci-local.sh              # THE gate: build, rebrand, test, clippy, fmt, receipt, docs — every step must report *-OK before pushing
scripts/ci-local.sh audit        # the supply-chain gates (cargo deny check + cargo audit) — CI runs them as separate fast jobs
scripts/ci-local.sh build|rebrand|test|clippy|fmt|receipt|docs    # one CI step at a time
scripts/mutants.sh [--list]      # #208 anti-vacuity mutants: apply each tested row's recorded mutant, run only its pinned tests, revert; a survivor is red naming the row
scripts/dev-test.sh [args...]    # `cargo test` with the CI env (debuginfo=0, no incremental, TMPDIR=target/tmp, --jobs 2) — the cheap path for "just run the tests" (issue #261)
cargo test -p phero-driver --test navigation      # one test suite
cargo test -p sigil-cli -p sigil-resolve -p sigil-lsp      # the imported Rune toolchain's suites (fixtures in tests/rune/; regen PHERO_UPDATE_FIXTURES=1; the CDM test skips unless scripts/rune/fetch-cdm.sh ran)
cargo run -p phero-cli -- check tests/conformance/                            # project mode + the union integrity pass: one snapshot of every supported surface under a dir; each file checks independently with its imports resolving map-first from the snapshot, then the standalone artifacts cluster into import-connected applications and the cross-layer wiring is diagnosed per application (formatter-golden `X.fmt.<ext>` artifacts are skipped — they are outputs whose imports/vocab resolve next to their sources, not standalone models)
cargo run -p phero-cli -- build tests/conformance/ -o target/phero               # project-mode artifact emission: one `<input path>.json` per file under the out dir (default `target/phero`), each the `pherolang ir` artifact for its surface
cargo run -p phero-cli -- graph build examples/ -o target/examples.graph.json   # one semantic graph artifact across every surface under the tree: import-connected applications, nodes, edges; display paths are base-relative POSIX
cargo run -p phero-cli -- graph query examples/artifacts/examples.graph.json affected-by 'capability:support/support.actor#Support.RaiseRefund'   # artifact-only query (`-` = stdin): node / list / affected-by / dependencies, one versioned envelope each
cargo run -p phero-cli -- graph query tests/conformance/graph/app.graph.json separation-of-duty --pair App.RaiseRefund App.ApproveRefund --fail-on-findings   # cross-policy analytics: separation-of-duty / monotonicity / dead-capabilities / reachability (exit 1 on a definite finding)
cargo run -p phero-cli -- explain E0104                                        # explain one diagnostic code from the phero-diagnostics registry (--list: the allocation ledger + every code)
cargo run -q -p phero-cli -- docs lint                                          # the documentation quality gate: content model, heading sets, terminology, and every compilable Guide example (docs/documentation/)
cargo run -p phero-cli -- highlight examples/support/support.mox --format json  # compiler-backed highlight artifact (--format html; `-` + --surface for a docs fence)
cargo run -q -p phero-cli -- grammar --check site/packages/highlighting      # generated editor grammar/config hand-edit guard (also CI step 6/8)
cargo test -p phero-highlight                                # taxonomy, engine, corpus, docs-fence summary, renderers, grammar package
cargo run -p phero-cli -- verify <files...> -o <receipt.json>                 # emit a verification receipt: source closure + artifact hashes + the register's rows, canonical and deterministic
cargo run -p phero-cli -- verify --check <receipt.json>                       # validate a receipt standalone — no register, models, toolchain, or network
cargo run -p phero-cli -- verify --check-fresh <receipt.json>                 # regenerate from the receipt's own inputs and byte-compare (the CI freshness gate)
scripts/regen-goldens.sh         # regenerate every golden in one pass (`--check`: fail if the tree goes dirty); the writer inventory and byte-shape rules are docs/GOLDENS.md
PHERO_UPDATE_FIXTURES=1 cargo test -p phero-verify  # regenerate the register tables in docs/VERIFICATION.md (hand-edit register.json, never the tables)
```

CI (`.github/workflows/ci.yml`) **invokes `scripts/ci-local.sh` for every gate** (build, rebrand, tests, clippy, fmt, receipt, docs) — the script is the single source of truth for the gate sequence and the `pherolang fmt --check` fixture-glob list (`FIXTURE_FORMAT_GLOBS`), so a new fixture directory is a one-file edit and local/remote can never drift (issue #121). CI also runs two fast supply-chain jobs: `cargo audit` (advisories — must stay at zero) and `cargo deny check` (advisories/licenses/bans/sources per `deny.toml`); the script's `audit` subcommand replicates both locally. A warning anywhere is a failure.

## Build cache (mbx)

`mbx` (mr boxington) is the machine-wide compilation cache. It matters most
here: a clean `cargo test --no-run` costs ~70–80 minutes and writes ~250 GB of
test artifacts (the issue #261 disk budget); through mbx the same build
restores from the local store in seconds, including after `target/` is wiped
or in a fresh worktree.

- **Run cargo through mbx.** `mbx setup` installs the cargo shim, so plain
  `cargo`, `scripts/ci-local.sh`, and `scripts/dev-test.sh` route through it
  automatically; or invoke `mbx build` / `mbx test` directly. Use one mode per
  checkout — alternating mbx and plain cargo recompiles build-script units.
- **The toolchain pin is a cache key.** `rust-toolchain.toml` pins 1.100.0;
  bump it in one deliberate commit. CI's `dtolnay/rust-toolchain@stable`
  runner resolves the pin through rustup. Never bump with a silent
  `rustup update`.
- **Keep `RUSTFLAGS` consistent per flavour.** `scripts/dev-test.sh` and
  `scripts/ci-local.sh` use `-C debuginfo=0` + `CARGO_INCREMENTAL=0`; a bare
  `cargo test` is a different key set. Mixing the two halves the hit rate.
- The scratch-crate e2e tests generate their own cargo projects under
  `target/scratch/` — they are separate builds and are not cached as units.
- **Store.** `~/.cache/mbx`, 90 GiB default budget with automatic GC. Test
  artifacts are the big consumer; `mbx cache stats` / `mbx gc --dry-run`
  inspect it. `.mbx.toml` opts test binaries into the machine-wide scheduler.
- Escape hatch: plain `cargo` keeps working; `MBX_*` variables disable
  individual features (https://mr-boxington.jdx.dev/configuration).

## Testing quirks

- **Golden fixtures** under `tests/conformance/` (IR artifacts, wire/api schemas, instances, fmt output) are byte-compared. Regenerate with `PHERO_UPDATE_FIXTURES=1`, then read the diff — goldens are the spec. Changing any emitter usually invalidates several goldens; body-less/vocabulary-less models must stay byte-identical.
- **Scratch-crate e2e** (`phero-backend-rust/tests/codegen_end_to_end.rs`): tests generate Rust code into a *separate cargo project* under `target/scratch/` and run `cargo test` in it (tries `--offline` first). Deleting `target/scratch/` is always safe; first run recompiles it (~10s). The scratch crate must keep `[workspace]` (empty) to stay out of ours.
- **Examples are CI-tested** (`examples/`): `examples_conformance` compiles each example, generates it into `target/scratch/phero-examples-test`, and runs behavioral assertions; `examples_schemas` validates `examples/instances/*.json` against generated wire schemas; `examples_cedar` (phero-backend-cedar) validates the `support` pair's Cedar output with the real `cedar-policy` crate under strict validation; `examples_artifacts` (phero-driver) compiles the artifact-surface examples (`.evt`/`.ddd`/`.uc`/`.deploy`/`.cmmn`) and byte-compares them against `examples/artifacts/` goldens; phero-backend-cmmn's examples test lowers `support.cmmn` to the cmmn-rs `CaseDefinition` JSON (`examples/artifacts/support.case.json`). Adding an example means adding its scratch assertions + instance (domain surfaces) or its artifact golden (artifact surfaces) — the harness fails otherwise. The domain-example list is hardcoded in three places: `examples_flow.rs`, `examples_schemas.rs`, and `phero-cli/tests/cli/`; the artifact-surface lists live in `crates/phero-driver/tests/examples_artifacts.rs` (with per-extension list↔disk sync tests); the `.ifml` examples (`examples/*/*.ifml`) have their own list in `crates/phero-ifml/tests/examples.rs` (compile + type-check + fmt-canonical + manifest byte-goldens under `examples/artifacts/<name>.manifest.json`); `phero-cli/tests/cli/` black-box `check`s the artifact examples too (`ARTIFACT_EXAMPLES`).
- **No network in tests**: `HttpProvider` is only URL-template unit-tested. `pherolang vocab fetch` is the only command that fetches.
- **The editor is one graph snapshot**: `.mox` drives the salsa session + `NavigationIndex`, `.ifml` its own one-shot compile + outline, and **every other surface** navigates through a directory-scoped graph snapshot, cached per directory and open `(uri, version)` set and rebuilt incrementally from a per-file content-hash memo. Diagnostics are each surface's own compile, never a second one. Resolution is the graph index's, locations the span tables'; an unbindable reference yields **no location, never an error**, and rename is declaration-owned and document-scoped (a cross-document rename is refused, naming the owning file). Contract: [docs/GRAPH.md](docs/GRAPH.md#the-lsp-contract).
- **LSP tests are in-process** via `LspService` + client socket (`tower-lsp` 0.20); the only subprocess test is the framed stdio handshake in `phero-cli`. Tests assert a compile counter (`initialized_service_counted`), never timing. The tower-lsp client socket is a **capacity-1 channel**: tests must interleave reads (`next_publish`/`drain_socket`) with opens or the server's publish send deadlocks the handler. The matrix tests live in `crates/phero-lsp/src/server/tests/graph.rs` (a temp copy of `tests/conformance/graph/app.*` plus the files the matrix needs).
- Wire-schema conformance validation uses the `jsonschema` crate against the committed golden schema; proptest suites (phero-backend-rust scratch, phero-backend-jsonschema) generate instances and validate round-trips — treat shrinking counterexamples as real bugs, not flaky tests.
- On this machine, `/tmp` is a small tmpfs and rustdoc doctest **linking SIGBUSes (or hangs) writing there**; run doctests (or full `cargo test`) with `TMPDIR` pointed at a disk-backed directory. Watch for orphaned `cargo`/`rustc`/`rust-lld` processes after killed builds — they stampede the load average and lock `target/`. **This hit CI too** (Oct 2026 incident: the runner's phero-driver doctests died with `ld terminated with signal 7 [Bus error]` and main stayed red for a day) — `.github/workflows/ci.yml` now frees runner disk, points `TMPDIR` at `target/tmp`, and caps the test step at `--jobs 2`; `scripts/ci-local.sh` replicates the eight CI steps locally. A `signal 7` in CI's Doc-tests section is resource exhaustion — check `df -h` in the log, don't hunt a compiler bug. Before pushing: run `scripts/ci-local.sh` until every step reports `*-OK`. Before branching: check main's latest run is green.

- **The build dir is a disk budget** (issue #261): cargo places integration-test binaries under `target/debug/build/<pkg>/<hash>/out/` and **never collects old hashes**; with the workspace default `debuginfo=2` a single worktree reached 104–119 GB (one crate's `build` dir alone: 104 GB). At 100% disk the symptom is exactly the one above — a doctest link dying with `ld terminated with signal 7 [Bus error]` — disk-induced, not a compiler bug: check `df -h` before hunting one. `scripts/ci-local.sh` exports `RUSTFLAGS="-C debuginfo=0"` + `CARGO_INCREMENTAL=0`, prints `df -h .` / `du -sh target` before the build step (and warns, never fails a gate, when free space is under `PHERO_DISK_MIN_GB`, default 20 GB), and clears stale `target/tmp` before the test step (it is recreated); `scripts/dev-test.sh` gives a plain `cargo test` the same env + `--jobs 2`. Reclaim with `rm -rf target/debug/build/phero-*` (**workspace crates only** — external deps survive; never delete `target/debug/build` wholesale, it is the live cache). Explicit decision: **no `[profile.dev] debug = 0`** in `Cargo.toml` — debugging the compiler with `debug=2` is valuable, and a profile change would alter fingerprints for every contributor and CI; the wrapper is the cheap path.

## Gotchas

- **Verification receipts are goldens too** (issues #197/#206/#207): `examples/artifacts/support.receipt.json` embeds the register's hash and rows, every `sources` hash, and every artifact hash, so *any* change to a source in the closure, an artifact golden, the register, or the generator version makes it stale. The `scripts/ci-local.sh receipt` step (CI step 6/7) fails with the exact regenerate command; run it and read the diff. `--check` is offline validation (receipt + sibling artifacts only); `--check-fresh` is the gate (it re-derives artifact goldens and re-reads the register). `mutantKilled` is `null` for every row plus `limits: ["mutants-unrecorded"]` until #208 lands — that is the honest interim, not a gap to paper over. Staleness classes and the schema live in `docs/RECEIPTS.md`.
- The proof-obligation register is **generated** (issue #203): `docs/verification/register.json` is the source — hand-edit it, never the tables — and the block between the `BEGIN/END GENERATED REGISTER` markers in `docs/VERIFICATION.md` is rendered from it by `PHERO_UPDATE_FIXTURES=1 cargo test -p phero-verify`. The drift gate (`crates/phero-verify/tests/trusted_register.rs`, the #89 lineage) fails on: a dead evidence pointer (missing file or absent `fn <symbol>`), a status outside `proved`/`tested`/`argued`/`assumed` (`"verified"` is rejected by name), an `argued`/`assumed`/mirrored row without a `trigger` + ISO `review` ≥ `reviewedAt`, a hold row without reason/trigger/review, a `#[trusted]` with no `trusted[]` entry, or a `trusted[]` entry with no `#[trusted]` in the tree (the check is **bidirectional**; the old one-way substring test is gone). `phero-evidence` owns the parse/validate/render; the gate owns the filesystem resolution.
- `pherolang graph build` (issue #240) is **derived post-compile — never parsed**: `commands/graph.rs` expands inputs exactly like `check`/`build` and hands `phero_driver::graph::build` each file's already-computed typed artifact and resolved imports (one `GraphInputs` bucket per surface; never a re-read or re-compile), best-effort over the compiling subset (exit `1`). There is no `pheroVersion`, determinism is the builder's, and the kind vocabulary is **open** — a new kind is a new string constant, not an enum variant. Golden: `PHERO_UPDATE_FIXTURES=1 cargo test -p phero-cli --test cli graph`. Contract: [docs/GRAPH.md](docs/GRAPH.md#the-pherolang-graph-build-command).
- `graph query` and the four cross-policy analytics run on the **artifact alone** (`GraphIndex`) — no sources, no recompile, no resolver — one versioned envelope each (`GRAPH_QUERY_FORMAT_VERSION`). Closures walk non-ownership edges reverse and `memberOf`/`contains` forward (`dependencies` mirrors it); every analytic stays **per application**, treats `when` guards as satisfiable, and never reports `unknown` (an opaque `cedar` grant) as a finding. `--fail-on-findings` exits `1` only on a definite finding. Contract: [queries](docs/GRAPH.md#queries), [analytics](docs/GRAPH.md#cross-policy-analytics); regenerate with `PHERO_UPDATE_FIXTURES=1 cargo test -p phero-driver --test graph_analytics`.
- **The span tables and the graph share one node table**: one pure, never-panicking builder per surface (`crates/phero-driver/src/navigation/`) derives every definition through `graph::ids` — the single naming source — and `IndexedReference`s carry `target_kinds` hints only, never a binding.
